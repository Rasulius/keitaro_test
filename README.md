# Keitaro Wrapper

Веб-приложение-обёртка над Keitaro (Admin API) из двух частей:

1. **Создатель кампаний** — создаёт в Keitaro кампанию с двумя потоками:
   - поток 1: трафик из указанной страны → редирект на Google (URL настраивается);
   - поток 2: остальной трафик → выбранный оффер.
2. **Редактор кампаний** — работа с потоками/офферами существующей кампании:
   - загрузка потоков из Keitaro (`Fetch Streams`),
   - черновик изменений (жёлтое состояние) и публикация в Keitaro (`Push to KT`) / отмена (`Cancel`),
   - добавление, удаление и возврат офферов (`Add / Remove / Bring Back`),
   - автоматический пересчёт весов (сумма 100%) и поддержка закрепления веса (`pin`),
   - сохранение архива удалённых офферов в обёртке и пометка `Removed` при внешнем удалении в Keitaro (с возможностью `Bring Back`).

Стек: **FastAPI + SQLAlchemy**. Фронтенд: статический **HTML/CSS/JavaScript** (Jinja2-шаблоны, без сборки).

## Быстрый старт

В папке проекта есть скрипты сборки, которые автоматически создают `.venv`, устанавливают зависимости, при необходимости создают `.env` из `.env.example` и применяют миграции Alembic.

### Windows (PowerShell)

```powershell
# сборка (подготовка окружения)
.\build.ps1

# сборка и запуск приложения
.\build.ps1 -Run
```

Полезные параметры: `-Run` (запуск после сборки), `-Reload` (автоперезагрузка, вместе с `-Run`), `-Recreate` (пересоздать `.venv`), `-Port 8002`, `-BindHost 0.0.0.0`, `-SkipMigrations`.

> Если выполнение скриптов запрещено политикой PowerShell, запустите: `powershell -ExecutionPolicy Bypass -File .\build.ps1 -Run`

### Linux / macOS / Git Bash

```bash
# при необходимости сделать скрипт исполняемым
chmod +x ./build.sh

# сборка (подготовка окружения)
./build.sh

# сборка и запуск приложения
./build.sh --run
```

Полезные параметры: `--run`, `--reload`, `--recreate`, `--port 8002`, `--host 0.0.0.0`, `--skip-migrations`.

После запуска откройте [http://127.0.0.1:8001/admin](http://127.0.0.1:8001/admin) и укажите **Keitaro URL** и **Admin API key** (сохраняются в локальный `runtime_config.json`, который не коммитится в Git). Подробная ручная установка описана ниже.

## Соответствие ТЗ (кратко)

- Кампании создаются с префиксом `test_фамилия_` (настраивается, по умолчанию в приложении — в настройках; пример из ТЗ: `test_ivanov_campaign1`).
- При создании задаются: название, гео-код страны, ID оффера; у кампании настраиваются домен, группа и источник трафика (выбор по названию из Keitaro, ID подставляется автоматически).
- В редакторе реализованы `Fetch Streams`, `Push to KT`, `Cancel`, `Add`, `Remove`, `Bring Back`, визуальные состояния (белый/жёлтый/серый, архив/Removed), пересчёт весов и `pin`.
- При `Fetch Streams` офферы, удалённые напрямую в Keitaro, не теряются бесследно: помечаются как удалённые (серые, 0%) и доступны для `Bring Back`.

> Примечание: точные имена полей/схем потоков Keitaro могут отличаться между версиями. Клиент и маппинг реализованы адаптерно (`app/keitaro/client.py`, сервисы), при необходимости их можно скорректировать под конкретный инстанс Keitaro.

### 1. Подготовка окружения

```bash
# из папки проекта
python -m venv .venv

# Windows PowerShell
.venv\Scripts\Activate.ps1

# Windows cmd
# .venv\Scripts\activate.bat

# Linux/macOS
# source .venv/bin/activate

pip install -r requirements.txt
```

### 2. Настройка подключения (без хранения секретов в Git)

Рекомендуемый способ — **встроенная страница настроек** приложения:

1. Запустите приложение (см. шаг 4).
2. Откройте `http://127.0.0.1:8001/admin` (вкладка **«Настройки»**).
3. Укажите:
   - **Keitaro URL** (например, `https://your-tracker-domain.com`)
   - **Admin API Key**
   - при необходимости значения по умолчанию: префикс кампаний, URL гео-редиректа, ID домена/группы/источника/оффера.
4. Сохраните. Настройки записываются в локальный файл **`runtime_config.json`** в корне проекта.

`runtime_config.json` добавлен в `.gitignore` и **не должен попадать в Git** (в нём хранится API-ключ).

Альтернативно (для разработки) можно использовать `.env`:

```bash
copy .env.example .env
# заполните значения
```

Приоритет: значения из `.env`/переменных окружения загружаются базово, а непустые значения из `runtime_config.json` применяются поверх них при работе приложения.

### 3. Миграции БД (опционально, но рекомендуется)

```bash
alembic upgrade head
```

Для SQLite при старте приложение также выполняет `create_all(...)` как bootstrap, поэтому для локального запуска можно обойтись без отдельного шага миграций. Для контролируемых изменений схемы используйте Alembic.

### 4. Запуск

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8001 --reload
```

Откройте в браузере:
- `http://127.0.0.1:8001/` — создатель кампаний
- `http://127.0.0.1:8001/editor` — редактор кампаний
- `http://127.0.0.1:8001/admin` — настройки (URL/API key/дефолты)

> Если порт `8001` занят, укажите другой (`--port 8002` и т.д.).

| Параметр | Где задаётся | Описание |
|---|---|---|
| `KEITARO_URL` | Настройки / `.env` | Базовый URL Keitaro |

## Использование

### Часть 1. Создатель кампаний (`/`)

1. Заполните название (к нему добавится префикс), гео-код страны (например `AU`) и ID оффера.
2. Выберите домен/группу/источник по названию (ID подставятся автоматически, поля ID только для чтения) или используйте значения по умолчанию.
3. Нажмите **«Создать кампанию»**.
4. После успешного создания отобразится результат и ссылка для открытия кампании в редакторе.

### Часть 2. Редактор кампаний (`/editor`)

1. Выберите кампанию из списка (доступны фильтр по имени и «только активные») или введите ID вручную.
2. Нажмите **`Fetch Streams`** для загрузки/синхронизации потоков из Keitaro.
3. Вносите изменения в черновик: `Add`, `Remove`, `Bring Back`, изменение/закрепление весов (`pin`).
4. Нажмите **`Push to KT`** для публикации изменений потока в Keitaro или **`Cancel`** для отката черновика.

## API приложения (основное)

- `GET /api/settings`, `POST /api/settings` — чтение/сохранение локальных настроек (секреты маскируются в ответе)
- `GET /api/campaigns` — список кампаний (поддерживает `q`, `state`, `active_only`)
- `POST /api/campaigns` — создание кампании с двумя потоками
- `GET /api/campaigns/{id}/editor` — локальное состояние редактора
- `POST /api/campaigns/{id}/fetch` — загрузка/синхронизация потоков из Keitaro
- `POST /api/editor/offers/add|remove|bring-back|pin` — операции с офферами в черновике
- `POST /api/editor/streams/push|cancel` — публикация/отмена изменений потока
- `GET /api/offers/search?q=...` — поиск офферов
- `GET /api/reference/domains|groups|traffic-sources` — справочники Keitaro

## Подготовка папки `deploy`

В репозитории/рабочей папке может присутствовать каталог `deploy` с очищенной копией проекта (без `.env`, `runtime_config.json`, БД, кэшей, исходных материалов/видео и прочих временных файлов), готовой к передаче или публикации. Перед запуском в `deploy` выполните сборку скриптом (`.\build.ps1` / `./build.sh`, см. раздел «Быстрый старт») или те же шаги вручную: установка зависимостей, настройка через `/admin` (или `.env`), запуск `uvicorn`.
